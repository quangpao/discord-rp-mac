CustomRPMenu Bar & Editor — Design Spec
macOS menu bar utility · spec v1.0

A custom Discord Rich Presence, told through the menu bar.

Two surfaces carry the product: the status-item dropdown and the compact editor window. This page is a redline spec — every metric below is the literal value the build must ship, and every panel is a 1:1 mock rendered with those values.

02

The open dropdown menu

The centrepiece. Rows are 22 px, the panel is 6 px radius with 4 px vertical / 5 px horizontal inner padding, and separators are 1 px lines with 5 px vertical margin. Presets live in exactly one submenu; nothing else nests. Panels open right-aligned to the screen edge, as status-item menus do on macOS.

Validation rules to surface in the UI

  • Details and State must each be at least 2 characters when non-empty; the inline hint reads “Details needs at least 2 characters”.
  • Button label must be ≤ 32 UTF-8 bytes (Discord’s limit); count bytes, not glyphs.
  • Timestamps are clamped to 1970-01-01T00:00:01Z … 5138-11-16T09:46:39Z; values outside the range are rejected, not silently truncated.
  • Image key is either an uploaded asset name or an absolute https URL; the resulting mp:external form must be ≤ 256 characters.
  • Party (size / max / current) is only valid for the Playing activity type.
  • Competing activity accepts no timestamps; the Time section is hidden and its values cleared when Competing is selected.
  • Maximum two buttons; the “+ Add button” affordance disables at 2 and reports “2/2 — maximum reached”.

Deliberately cut for compactness

The menu is capped at 11 rows and exactly one status line. These items were removed; each either duplicates an action reachable elsewhere or is too rare to earn a permanent row.

  • About CustomRP / version — moved to the standard About panel in Settings.
  • Check for Updates… — Sparkle handles it automatically; manual check lives in Settings.
  • Copy / Paste presence JSON — developer affordance, moved to Settings ▸ Advanced.
  • Pause / Resume presence — collapsed into Clear Presence + Reapply Now.
  • Auto-reconnect toggle — always on; exposing it invited a broken state.
  • Refresh preset list — presets are file-observed and refresh themselves.
  • Inline per-preset Edit / Duplicate / Delete — would force a third submenu level; all moved to “Manage presets…”.
  • “Recent presets” nested submenu — a second submenu; presets already fit in one.
  • Second live status line / presence preview — breaks the one-status-line rule.
  • Set as default preset — the checkmark on activation already communicates this.
  • Export / Import all presets — Settings ▸ Presets.
  • Open Logs / Report an issue / Support — help menu in the app itself.
  • Keyboard-shortcut cheat sheet — the three shortcuts are inline where they apply.
