CustomRPby quangpao — a menu bar app for Discord Rich Presence

A native macOS menu bar utility that sets a custom Discord Rich Presence, so your Discord profile shows what you are doing right now. Below are three distinct marks, each delivered as a colour SVG, a monochrome template image, and an app-icon build, with copyable source throughout.

C

The two rules every mark obeys

Rule 01

Legible at 16 px

No stroke thinner than 1.5 units on a 32-unit canvas, no cut-out that closes up, no detail that asks for more pixels than a menu bar gives. Each silhouette resolves in about 2–3 shapes.

Rule 02

One silhouette

Every mark reads as a single unified form. Nothing decorative floats free of it, and the same shapes survive a flat one-colour template render with no gradients or shadows.

01
Presence Green

Presence Pulse

Online, and broadcasting what you are doing — a lit status dot with an open halo.

The idea. A solid centre dot is the universal "I am here" signal; the arc around it is the halo ringing outward. The arc stays open at the top-right, so the silhouette reads as something emitting rather than as a closed record button or a target. It is the least literal of the three: it says live and visible without drawing a bolt or a letter, which makes it the safest choice if the app is ever renamed.

Where the silhouette comes from. A filled circle, one concentric stroke of heavier weight around it, and a 45° gap on the upper-right diagonal. The dot fills roughly half the inner void, so the gap never crowds the ring at small sizes.

When not to use it. Do not use it where a generic status dot already lives — notification badges, presence pills, recording indicators — because it will be read as part of that system rather than as the app. It is also the weakest of the three when the mark has to carry the product name, since there is nothing letterform-like in it.

      02
      

        Activity Amber
        
Activity Spark

        
A replacement for the bolt: a four-point energy spark carrying its own status light.

      

    

    

      

        
The idea. The glyph the app ships with is the system's generic "power" bolt — every third-party utility owns a version of it, so it can never be the app's. The spark keeps the meaning ("something is happening right now") but moves the reading from electricity to a live event. The small filled dot in the spark's upper notch is the status light: the spark is the activity, the dot is the app watching it.

        
Where the silhouette comes from. One four-point star with deeply concave sides, drawn as a single closed path, plus one small circle placed in the concave gap between the top and right arms. Two shapes, no hairlines, nothing filled on top of anything else.

        
When not to use it. Avoid it where an assistant or "AI action" sparkle already lives, or it will be mistaken for a generate button. Avoid it beside warning or power controls too, where a star reads as a fault badge rather than a status.

      03
      

        Monogram Sky
        
Q Monogram

        
A "Q" for quangpao whose tail lands as a presence dot.

      

    

    

      

        
The idea. The author's initial is the one asset no other app can copy, so the third concept leans on it. The bowl of the Q is a heavy ring — it reads at 16 px as a ring, not a blob — and the tail cuts out of the lower-right diagonal, ending in a rounded terminal that doubles as the presence dot. The counter stays open enough that the letter never collapses into an O or a zero.

        
Where the silhouette comes from. A stroked ring at radius 8.5 with a 5.5-unit stroke, plus one diagonal stroke of the same weight that starts inside the ring band and exits at 45°, ending in a round cap. Two strokes, and the cap is the status dot.

        
When not to use it. Avoid it for a second product from the same author, and avoid it in a header that is already full of letterforms — a monogram only wins when it is the only letter on screen. It is also the least descriptive of the three: it says whose app it is, not what it does.

      05
      

        
Implementation notes

        
What each code block becomes, how the template variant is wired into a menu bar item, and where the credit line goes.

      

    

    

      

        

          
File map

          

            
FileUsed for

            
              
mark.svgColour mark. About panel, README header, website, release notes. Keep the hard-coded hex; it is not tinted at runtime.

              
mark-template.svgMenu bar item. Single-colour currentColor shapes only. Rendered through a template image so macOS handles appearance.

              
appicon.svgApp-icon source. 256-unit squircle at a 22.37% corner radius; export the PNG sizes Xcode needs from it.

            
          

        

        

          
Using the template in a menu bar item

          
Load mark-template.svg, then set the image as a template so AppKit ignores the colours in the file and paints it with the correct menu bar tint instead:

          
image.isTemplate = true  ·  image.size = NSSize(width: 18, height: 18)

          
Because the file defines a 32-unit viewBox with a 2.75-unit stroke, it stays crisp from 16 px through 44 px with no separate asset. Keep it free of gradients, shadows, and multi-colour fills — a template image is flattened to one alpha mask, so any tone you add is discarded anyway.

          
For the selected state macOS inverts the tint automatically; do not ship a second "highlighted" file.

        

      

      

        
Accessibility and addressing

        
The colour mark carries a role="img" and a label. The menu bar item should carry a real accessibility label such as "CustomRP — Rich Presence active", not the mark's own text, because the item reports state rather than identity.

        
Every swatch, mark card, menu bar strip, app icon, wordmark and code block above has a stable data-od-id so a reviewer can point at one and have it changed by name.
